# 第2回 アセンブラハンズオン案

## この資料の位置づけ

この資料は、旧 ATTiny85 演習で扱っていた

- LED の点灯
- LED の消灯
- LED の反転
- レジスタやビット操作の感覚

を、`Raspberry Pi Pico 2 W with headers` の `Cortex-M33` 向けに作り直すための再構成案です。

今回は教材の対象を `Cortex-M33` に絞り、別環境が必要な Linux 向け演習や ARM64 向け演習は含めません。

---

## 基本方針

この回では、次の 3 つを結び付けて学びます。

- C のビット演算や条件分岐
- Cortex-M33 の命令
- 実機の LED 制御

演習はすべて `Pico 2 W` 実機上で進めます。受講生が環境切り替えで混乱しないように、題材は 1 本に絞ります。

---

## 到達目標

この回の到達目標は次のとおりです。

- C からアセンブラ関数を呼び出せる
- LED をアセンブラから点灯、消灯、反転できる
- `EOR` によるビット反転の意味を説明できる
- `CBZ` / `CBNZ` を使った分岐の考え方を理解する
- `UBFX` / `BFI` でビットフィールド操作を説明できる
- `RBIT` / `REV` / `CLZ` のような専用命令の利点を理解する

---

## 全体構成

授業の流れは次のようにします。

1. C 版で LED を点滅させる
2. アセンブラで LED を ON / OFF する
3. アセンブラで LED を TOGGLE する
4. ボタン入力と `CBZ` / `CBNZ` を組み合わせる
5. `UBFX` / `BFI` でビットフィールド操作を試す
6. `RBIT` / `REV` / `CLZ` をシリアル出力で観察する
7. 余裕があれば `LDREX` / `STREX` を発展として扱う

## 実装方針

今回は **インラインアセンブラではなく `.S` ファイル方式** を使います。

理由は次の通りです。

- 命令が見やすい
- C と asm の境界が分かりやすい
- 配布教材として扱いやすい
- 穴埋め演習に向く

役割分担は次のようにします。

- `main.ino`
  - GPIO 初期化
  - `loop()`
  - シリアル出力
  - ボタン入力
- `led_asm.S`
  - LED 状態の ON / OFF / TOGGLE
  - `CBZ`
  - `UBFX` / `BFI`
  - `RBIT` / `REV` / `CLZ`

## 最初の実機演習

最初は C 版の L チカを成功させます。

狙いは次の 2 点です。

- 配線が正しいことを確認する
- ボード書き込みの問題を先に潰す

この段階では、アセンブラの問題とハードウェアの問題を分離します。

## 演習の核: LED ON / OFF / TOGGLE

旧 ATTiny85 演習の核は、LED の操作でした。今回もそこはそのまま残します。

段階は次の 3 つです。

1. `led_on_asm()`
2. `led_off_asm()`
3. `led_toggle_asm()`

この順にすると、受講者は

- ビットを立てる
- ビットを落とす
- ビットを反転する

をきれいに区別して学べます。

---

## `EOR` を主役にする理由

LED 反転には `EOR` がとても向いています。

対応する C のイメージは次です。

```cpp
state ^= 1;
```

1 ビットだけ反転する、という操作がそのまま命令に対応して見えるため、教材として非常に美しい題材です。

学べること:

- XOR の意味
- ビットマスク
- read-modify-write
- 反転操作の感覚

---

## `CBZ` / `CBNZ`

次の題材は `CBZ` / `CBNZ` です。

- `CBZ`
  - 値が 0 なら分岐
- `CBNZ`
  - 値が 0 でなければ分岐

ボタン入力やフラグ判定のような、「0 かどうか」で十分な場面にとてもよく合います。

演習では、

- C 側でボタン値を読む
- asm 側で 0 判定する

という流れにすると理解しやすくなります。

---

## `UBFX` / `BFI`

マイコンのレジスタ操作では、「全部ではなく一部のビットだけ扱う」ことが頻繁にあります。

そこで、次の命令を扱います。

- `UBFX`
  - ビットフィールドの取り出し
- `BFI`
  - ビットフィールドの埋め込み

これにより、C の次のような式との対応を学べます。

```cpp
mode = (reg >> 4) & 0x3;
reg = (reg & ~(0x3 << 4)) | (value << 4);
```

---

## `RBIT` / `REV` / `CLZ`

ここでは「専用命令があるとうれしい」例を見せます。

- `RBIT`
  - ビット順反転
- `REV`
  - バイト順反転
- `CLZ`
  - 先頭ゼロ数

これらは LED 制御そのものには不要ですが、

- ビット列の向き
- データ表現
- ループなしでできる処理

を学ぶ小演習としてとても良い題材です。

---

## 発展: `LDREX` / `STREX`

時間があれば、共有状態の更新についても触れます。

- `STREX`

## 演習課題と提出条件

### 課題 A: LED ON / OFF / TOGGLE

次の 3 つの関数を完成させてください。

- `led_on_asm()`
- `led_off_asm()`
- `led_toggle_asm()`

要求動作は次の通りです。

- `led_on_asm()` 呼び出し後に LED が点灯する
- `led_off_asm()` 呼び出し後に LED が消灯する
- `led_toggle_asm()` を 2 回連続で呼ぶと、LED 状態が 2 回反転して元に戻る

### 課題 B: 分岐

`CBZ` または `CBNZ` を使って、ボタンが押されたときだけ LED を反転する処理を実装してください。

### 課題 C: ビット演算デモ

次の命令について、サンプル値を入力した結果をシリアルモニタに表示してください。

- `UBFX`
- `BFI`
- `RBIT`
- `REV`
- `CLZ`

### 提出物

提出時には次の 3 点をそろえてください。

1. `main.ino`
2. `led_asm.S`
3. 動作確認結果をまとめた短いレポート 1 本

### レポートに必ず含める内容

レポートには次の 5 項目を必ず書いてください。

1. `EOR` が LED 反転に向いている理由を 2 行以上で説明する
2. `CBZ` または `CBNZ` をどこで使ったかを書く
3. `UBFX` の入力値と出力値を書く
4. `BFI` の入力値と出力値を書く
5. `RBIT`、`REV`、`CLZ` のうち 1 つを選び、C で書くより命令が分かりやすい理由を書く

### 合格条件

次の条件をすべて満たしたものを完了とします。

- `main.ino` と `led_asm.S` がコンパイル可能である
- LED の ON / OFF / TOGGLE が実機で確認できる
- ボタン押下で LED 反転が実行される
- シリアルモニタにビット演算デモの結果が出力される
- レポートに必須 5 項目がすべて含まれている
