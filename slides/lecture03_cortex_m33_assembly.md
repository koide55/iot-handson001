# 第3回 Cortex-M33 アセンブラハンズオン

## この資料の目的

この回では、`Raspberry Pi Pico 2 W with headers` の `Cortex-M33` を題材に、マイコン向けアセンブラの考え方を体験します。

狙いは、単に命令を暗記することではありません。次の 3 つを結び付けて理解することです。

- C のビット演算や分岐
- Cortex-M33 の命令
- 実機の GPIO 制御

この回では、特に次の命令や機能を取り上げます。

- `EOR`
- `CBZ` / `CBNZ`
- `UBFX` / `BFI`
- `RBIT` / `REV` / `CLZ`
- `LDREX` / `STREX` は発展

演習前のやさしい予習資料として、次も参照してください。

- [第2.5回 Cortex-M33 アセンブラ超入門](lecture02a_cortex_m33_assembly_primer.md)

## 2. Cortex-M33 とは

`Cortex-M33` は、`Armv8-M Mainline` 系のマイコン向けコアです。

この回では、次のような「実機を気持ちよく触れる命令」を中心に扱います。

- 短い条件分岐
- ビット反転
- ビットフィールド操作
- ビット順やバイト順の変換

つまり、命令そのものの珍しさよりも、**1 命令の効果が GPIO やデータ表現に直結する** ところを体験する回です。

---

## 3. なぜインライン asm ではなく `.S` か

今回は、Arduino IDE でも **インラインアセンブラではなく `.S` ファイルを使う** 方針にします。

理由は次の通りです。

- C と asm の境界が見やすい
- 命令そのものに集中しやすい
- 将来 `RISC-V Hazard3` 版を作るときに差し替えやすい
- 長くなるとインライン asm は読みにくい

この回では、次のような役割分担にします。

- `pico2w-cortexm33-asm-worksheet.ino`
  - GPIO 初期化
  - `loop()`
  - ボタン入力
- `led_asm.S`
  - LED を ON / OFF / TOGGLE する関数

## 4. 最初に C 版で成功させる

まずは配線や書き込みの問題を切り分けるために、C 版で LED を点滅させます。

```cpp
const int LED_PIN = 15;

void setup() {
  pinMode(LED_PIN, OUTPUT);
}

void loop() {
  digitalWrite(LED_PIN, HIGH);
  delay(300);
  digitalWrite(LED_PIN, LOW);
  delay(300);
}
```

これが動いてからアセンブラへ進みます。

## 7. C から asm を呼び出す

`.ino` 側では、アセンブラ関数を次のように宣言します。

```cpp
extern "C" void led_on_asm(uint32_t* state);
extern "C" void led_off_asm(uint32_t* state);
extern "C" void led_toggle_asm(uint32_t* state);
```

最初のループは次のようにできます。

```cpp
volatile uint32_t g_led_state = 0;

void loop() {
  led_on_asm((uint32_t*)&g_led_state);
  apply_led_state();
  delay(300);
  led_off_asm((uint32_t*)&g_led_state);
  apply_led_state();
  delay(300);
  led_toggle_asm((uint32_t*)&g_led_state);
  apply_led_state();
  delay(300);
}
```

`apply_led_state()` は、状態変数 `g_led_state` の bit 0 を見て実際の LED を点灯・消灯させる C 側の関数です（`.ino` に定義）。

ここでは、「C から見れば普通の関数」であることが大事です。

---

## 8. 最初の目標: LED ON

最初の関数は `led_on_asm()` です。

考え方は単純です。

1. 引数 `r0` から状態変数 `*state` のアドレスを受け取る
2. LED に対応するビットマスク（bit 0）を作る
3. そのビットを 1 にして書き戻す

この「ビットを 1 にする」が、マイコンの低レベル制御の基本です。実機の GPIO レジスタを直接叩く代わりに、まずはメモリ上の状態変数で read-modify-write の感覚をつかみます（`apply_led_state()` がその状態を LED へ反映します）。

---

## 9. LED OFF

次は `led_off_asm()` です。

やることは ON の反対です。

1. 同じ状態変数を見る
2. 同じビット位置（bit 0）を使う
3. そのビットを 0 にして書き戻す

ここで受講者に意識してほしいのは、

- LED という物理デバイスも
- メモリ中の 1 ビットの状態で制御されている

という点です。

---

## 10. 一番大事な演習: LED TOGGLE

旧 ATTiny85 演習の核だった「LED 反転」を、今回は `Cortex-M33` で再構成します。

反転は、ビット操作の感覚をつかむのにとても良い題材です。

対応する C のイメージは次です。

```cpp
*state ^= 1;   // bit 0 を反転
```

アセンブラでは、ここで `EOR` が主役になります。

---

## 11. `EOR` がなぜ気持ちいいか

`EOR` は、同じビットが 2 回現れると 0 になり、違えば 1 になります。

そのため、あるビットに対して

- 0 なら 1 に
- 1 なら 0 に

できます。

つまり、`LED_MASK` を使って `EOR` すると、LED に対応するビットだけを反転できます。

この命令 1 個で「点灯と消灯をひっくり返す」という動きが表現できるのが、この回の気持ちよさです。

---

## 12. `EOR` のイメージ

たとえば LED の状態を bit 0 で表すとすると、

```text
元の状態    0000 0000
LED_MASK    0000 0001
EOR 後      0000 0001
```

もう一度同じマスクで `EOR` すると、

```text
元の状態    0000 0001
LED_MASK    0000 0001
EOR 後      0000 0000
```

となって元に戻ります。

## 18. `UBFX` / `BFI`

ここからは、`Cortex-M33` でぜひ教えたい「ビットフィールド操作」の命令です。

- `UBFX`
  - unsigned bit-field extract
- `BFI`
  - bit-field insert

これらは、レジスタの一部だけを抜き出したり、埋め込んだりする命令です。

---

## 19. なぜビットフィールド命令がうれしいか

マイコンのレジスタは、1 ワード全体を丸ごと使うよりも、次のように一部分だけ意味があることが多いです。

- 2 ビットでモード指定
- 1 ビットで有効 / 無効
- 数ビットでピン番号

そのため、

- `UBFX` で「一部だけ読む」
- `BFI` で「一部だけ書く」

という発想は、教材としてとても自然です。

---

## 20. C で書くとこうなる

ビットフィールドを C で扱うと、たとえば次のようになります。

```cpp
mode = (reg >> 4) & 0x3;
reg = (reg & ~(0x3 << 4)) | ((value & 0x3) << 4);
```

この式を読めることは大事ですが、少し見通しが悪くなります。

そこで、

- 抜き出すなら `UBFX`
- 埋め込むなら `BFI`

という専用命令があるのが `Cortex-M33` の面白さです。

## 22. `RBIT`, `REV`, `REV16`, `CLZ`

ここでは「ループで頑張るより専用命令がきれい」という例を見ます。

- `RBIT`
  - ビット順を反転
- `REV`
  - バイト順を反転
- `REV16`
  - 半語単位でバイト順を反転
- `CLZ`
  - 先頭ゼロ数を数える

---

## 23. どんなときに使うか

これらは一見マニアックですが、用途は意外と身近です。

- 通信データの並び替え
- ビット列の可視化
- ビットマップ処理
- 先頭に立っているビット位置の計算

`CLZ` は「何ビット必要か」を求める話にもつながります。

## 25. 発展: `LDREX` / `STREX`

余裕があれば、排他アクセス命令に触れます。

- `LDREX`
  - 排他的ロード
- `STREX`
  - 排他的ストア

これは「自分が読んでから書くまでの間に、誰かが触っていないか」を確かめながら更新するための仕組みです。

## 26. なぜマイコンでも必要か

マイコンでも、次のような場面では共有状態を安全に更新したくなります。

- メインループと割り込みの共有変数
- フラグの更新
- 小さなロック

この段階では、完全理解よりも「普通の `LDR/STR` だけでは足りないことがある」と知るだけで十分です。

## 29. Cortex-M33 らしい美しさ

`Cortex-M33` の美しさは、次のようなところにあります。

- 短い分岐
- ビットフィールド処理
- 実機制御に直結するビット演算

つまり、抽象的な計算よりも、

- 1 ビットだけ反転する
- 一部のビットだけ抜き出す
- 0 なら分岐する

といった操作がそのまま機械語として見えるところに面白さがあります。

## 30. まとめ

この回では、`Pico 2 W` の `Cortex-M33` を使って、マイコン向けアセンブラの入口を体験しました。

流れとしては次の通りです。

1. C でまず成功させる
2. asm で LED を ON / OFF / TOGGLE する
3. `CBZ/CBNZ` で分岐を短くする
4. `UBFX/BFI` でレジスタの一部を扱う
5. `RBIT/REV/CLZ` で専用命令のありがたさを見る
6. 余裕があれば `LDREX/STREX` へ進む

この続きとしては、次の発展が考えられます。

- PIO を使ったハード制御
- TrustZone for Armv8-M の導入
- 割り込みハンドラを含む asm 演習
- GPIO レジスタ直操作版への発展
